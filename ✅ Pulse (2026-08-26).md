# Pulse (Dota 2 Events Calendar)

## Que es
App para Android que muestra el calendario de próximos partidos profesionales de Dota 2, permite marcar equipos favoritos, y avisa por notificación con anticipación cuando juega un equipo favorito. Uso personal (sin login, sin código de vinculación entre dispositivos — ver Decisiones).

## Como se ve y funciona
Navegación por **menú hamburguesa** (drawer) con 7 secciones:
- **Calendario**: selector de fecha horizontal (14 días) + partidos del día, favoritos resaltados, filtro "Solo favoritos", ordenar por Hora/Torneo, badge "EN VIVO" con marcador en tiempo real.
- **Seguimiento**: calendario mensual con solo partidos de tus favoritos.
- **Equipos**: buscador + filtro por región (mismos colores que el anillo del logo) + marcar/desmarcar favorito.
- **Favoritos**: lista de equipos marcados.
- **Torneos**: pestañas En curso / Próximos / Finalizados, con tier, tipo, premio, país, ganador.
- **Ajustes**: anticipación del aviso (15min/30min/1h/3h/1día), toggle de notificación fija, y número de versión instalada al final.
- **Noticias**: feed oficial de Valve + prensa de esports.

Tocar un partido abre el **detalle** (equipos, hora en Perú, historial cara a cara). Tocar un equipo abre su **perfil** (próximos partidos).

**Notificaciones — sistema híbrido**: cuando un equipo favorito juega dentro del tiempo de anticipación configurado, el aviso llega de dos formas independientes para máxima confiabilidad — (1) un servidor en GitHub Actions revisa cada 15 min y manda un push real por Firebase Cloud Messaging, y (2) la propia app programa una notificación local de respaldo en el celular cada vez que se abre. Además hay una **notificación fija** (opcional, activable en Ajustes) que muestra siempre el próximo partido favorito en la barra de Android, no se puede deslizar para cerrar, y se actualiza sola (servicio nativo en primer plano) aunque la app esté cerrada del todo — incluso sin partidos favoritos todavía muestra un aviso neutro ("Sin partidos favoritos próximos") en vez de fallar.

**Hora de Perú, siempre**: todas las horas de partidos se muestran en huso horario de Perú (UTC-5 fijo) en formato 12 horas — `src/lib/peruTime.ts`.

**Diseño visual**: paleta oscura (fondo casi negro), encabezado azul claro con texto oscuro, acento azul, tarjetas con bordes redondeados y sombra, colores por tier de torneo (dorado/plata/bronce/azul/gris) y por región de equipo (anillo alrededor del logo), partidos en vivo con borde/resplandor rojo animado. Contenido siempre respeta la barra de estado (arriba) y la barra/gestos de navegación (abajo) — modo edge-to-edge de Android 15+ manejado correctamente.

## Stack
- **React Native 0.81.4** (TypeScript, New Architecture/Fabric) — reemplaza Flutter. Solo Android (se dejó de dar soporte a Windows a pedido del usuario).
- **Supabase** (Postgres + RLS) — reemplaza Firebase Firestore. Solo lectura pública de datos (partidos/equipos/torneos/noticias), sin Auth. Proyecto: `pulse-dota` (ref `unbzfwcmbxjfneyxgbru`).
- **Firebase Cloud Messaging** — se mantiene, únicamente para el push del híbrido de notificaciones (excepción justificada: Supabase no tiene servicio de push a celulares).
- **Zustand** — manejo de estado (favoritos y ajustes, persistidos localmente con AsyncStorage).
- **@react-navigation** (drawer + native-stack) — navegación.
- **@notifee/react-native** — notificaciones locales programadas.
- **react-native-url-polyfill** — polyfill de `URL` requerido por Supabase-js en Hermes (sin esto la app crashea al iniciar el cliente de Supabase).
- **Módulo nativo propio** (Kotlin, `PersistentNotificationService` + Foreground Service) — la notificación fija.
- **Node.js** (`scripts/`) — 5 scrapers + 1 script de notificaciones, corren vía GitHub Actions programado.
- **Velopack** no aplica (es móvil, no Windows) — auto-actualización vía GitHub Releases + instalador nativo de APK.

## Decisiones (excepciones justificadas al pedido inicial)
1. **Se eliminó el sistema de código de 6 dígitos y la sincronización entre dispositivos** — a pedido explícito del usuario tras revisar que no era necesario para una app de calendario sin datos privados que proteger. Favoritos y ajustes ahora son 100% locales por dispositivo (`AsyncStorage`).
2. **Se mantuvo Firebase Cloud Messaging** (único resto de Firebase) para el push del sistema híbrido de notificaciones — Supabase no ofrece push a móviles, y el usuario prefirió confiabilidad extra sobre simplicidad máxima.
3. **Se mantuvo la notificación fija de Android** (requiere módulo nativo Kotlin con Foreground Service) — a pedido explícito del usuario, pese a ser la pieza más "nativa" del proyecto.
4. **Mismo `applicationId` (`com.dotaschedule.dota_schedule`) pero keystore de firma NUEVO** — la contraseña del keystore original de la versión Flutter se perdió (confirmado irrecuperable, `.7z` de respaldo eliminado). Se generó un keystore nuevo desde cero. Consecuencia real: quien tenga la app Flutter vieja instalada **debe desinstalarla primero** — Android no deja instalar un APK con el mismo `applicationId` pero firma distinta encima de uno ya instalado. Las próximas actualizaciones (desde esta versión en adelante) sí se instalan solas sin problema.
5. **Limpieza total del proyecto Flutter anterior** — a pedido explícito del usuario ("no me gusta dejar proyectos perdidos"): carpeta `project-flutter-old/` eliminada, datos de Firestore eliminados, usuarios de Firebase Auth eliminados, repo de GitHub viejo (`dota-schedule`) eliminado.

## Archivos clave
- `services/localReminders.ts` + `services/pushNotifications.ts`: las dos mitades del sistema híbrido de notificaciones.
- `android/.../PersistentNotificationService.kt`: Foreground Service que muestra la notificación fija, se refresca solo cada 60s, sobrevive con la app cerrada, siempre llama `startForeground()` primero (incluso sin partidos) para cumplir el requisito de Android.
- `android/.../MainApplication.kt`: `SoLoader.init(this, OpenSourceMergedSoMapping)` — obligatorio en RN 0.81 por el "SO merging" (varias librerías nativas se fusionan en `libreactnative.so`).
- `index.js`: importa `react-native-url-polyfill/auto` como la primerísima línea — sin esto, Supabase-js crashea al iniciar.
- `android/app/build.gradle`: `versionName` se deriva automáticamente de `package.json` (fuente única de verdad) — evita que el chequeo de actualizaciones de la app quede desincronizado con el build nativo.
- `scripts/supabase-admin.mjs`: cliente de Supabase con la service role key, usado solo por los scripts (nunca en el cliente).
- `src/lib/deviceId.ts` + `services/deviceSubscription.ts`: reemplazo del "código de 6 dígitos" — cada instalación genera un UUID local propio para registrar su token FCM + favoritos en `device_subscriptions`, sin login.

## Instalar y correr
Dentro de `project/`:
```

```

```

```

## Auto-actualización
Sí, vía GitHub Releases — repo: `AndreDiaz11/pulse`. El APK se descarga e instala directo desde la app (`services/apkInstaller.ts`, patrón `REQUEST_INSTALL_PACKAGES`). `versionName` se deriva de `package.json` (fuente única) para que el chequeo de versión nunca quede desincronizado del build real.

**CI de release optimizado**: el pipeline (`release.yml`) usa cache de Gradle y npm. Como GitHub Actions aísla los caches por rama/tag y `release.yml` solo dispara en tags, se agregó `warm-cache.yml` (corre en cada push a `main`, mismo commit que después se etiqueta) para dejar el cache listo bajo el scope de la rama por defecto, que sí es visible desde cualquier tag.
