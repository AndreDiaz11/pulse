# Pulse (Dota 2 Events Calendar)

## Que es
App para Android que muestra el calendario de próximos partidos profesionales de Dota 2, permite marcar equipos favoritos, y avisa por notificación con anticipación cuando juega un equipo favorito. Uso personal (sin login, sin código de vinculación entre dispositivos — ver Decisiones).

## Como se ve y funciona
Navegación por **menú hamburguesa** (drawer) con 7 secciones:
- **Calendario**: selector de fecha horizontal (14 días) + partidos del día, favoritos resaltados, filtro "Solo favoritos", ordenar por Hora/Torneo, badge "EN VIVO" con marcador en tiempo real.
- **Seguimiento**: calendario mensual con solo partidos de tus favoritos.
- **Equipos**: buscador + filtro por región (mismos colores que el anillo del logo) + marcar/desmarcar favorito.
- **Favoritos**: lista de equipos marcados.
- **Torneos**: pestañas En curso / Próximos / Finalizados, con tier, tipo, premio, país, ganador.
- **Ajustes**: anticipación del aviso (15min/30min/1h/3h/1día) y toggle de notificación fija.
- **Noticias**: feed oficial de Valve + prensa de esports.

Tocar un partido abre el **detalle** (equipos, hora en Perú, historial cara a cara). Tocar un equipo abre su **perfil** (próximos partidos).

**Notificaciones — sistema híbrido**: cuando un equipo favorito juega dentro del tiempo de anticipación configurado, el aviso llega de dos formas independientes para máxima confiabilidad — (1) un servidor en GitHub Actions revisa cada 15 min y manda un push real por Firebase Cloud Messaging, y (2) la propia app programa una notificación local de respaldo en el celular cada vez que se abre. Además hay una **notificación fija** (opcional, activable en Ajustes) que muestra siempre el próximo partido favorito en la barra de Android, no se puede deslizar para cerrar, y se actualiza sola (servicio nativo en primer plano) aunque la app esté cerrada del todo.

**Hora de Perú, siempre**: todas las horas de partidos se muestran en huso horario de Perú (UTC-5 fijo) en formato 12 horas — `src/lib/peruTime.ts`.

**Diseño visual**: paleta oscura (fondo casi negro), encabezado azul claro con texto oscuro, acento azul, tarjetas con bordes redondeados y sombra, colores por tier de torneo (dorado/plata/bronce/azul/gris) y por región de equipo (anillo alrededor del logo), partidos en vivo con borde/resplandor rojo animado.

## Stack
- **React Native 0.81.4** (TypeScript) — reemplaza Flutter. Solo Android (se dejó de dar soporte a Windows a pedido del usuario).
- **Supabase** (Postgres + Realtime) — reemplaza Firebase Firestore. Solo lectura publica de datos (partidos/equipos/torneos/noticias), sin Auth.
- **Firebase Cloud Messaging** — se mantiene, unicamente para el push del hibrido de notificaciones (excepcion justificada: Supabase no tiene servicio de push a celulares).
- **Zustand** — manejo de estado (favoritos y ajustes, persistidos localmente con AsyncStorage).
- **@react-navigation** (drawer + native-stack) — navegacion.
- **@notifee/react-native** — notificaciones locales programadas.
- **Modulo nativo propio** (Kotlin, `PersistentNotificationService`) — la notificacion fija con servicio en primer plano.
- **Node.js** (`scripts/`) — 5 scrapers + 1 script de notificaciones, corren via GitHub Actions programado, sin cambios de logica salvo el destino (Supabase en vez de Firestore).
- **Velopack** no aplica (es movil, no Windows) — auto-actualizacion via GitHub Releases + instalador nativo de APK (mismo patron ya usado, ver Auto-actualizacion).

## Decisiones (excepciones justificadas al pedido inicial)
1. **Se elimino el sistema de codigo de 6 digitos y la sincronizacion entre dispositivos** — a pedido explicito del usuario tras revisar que no era necesario para una app de calendario sin datos privados que proteger. Favoritos y ajustes ahora son 100% locales por dispositivo (`AsyncStorage`).
2. **Se mantuvo Firebase Cloud Messaging** (unico resto de Firebase) para el push del sistema hibrido de notificaciones — Supabase no ofrece push a moviles, y el usuario prefirio confiabilidad extra sobre simplicidad maxima.
3. **Se mantuvo la notificacion fija de Android** (requiere modulo nativo Kotlin con Foreground Service) — a pedido explicito del usuario, pese a ser la pieza mas "nativa" del proyecto.
4. **Mismo `applicationId` (`com.dotaschedule.dota_schedule`) y mismo keystore de firma que la version Flutter** — para que la actualizacion se instale encima de la app ya instalada por usuarios actuales, sin pedir reinstalar ni perder datos. El keystore vive cifrado en `secretos/dota-schedule-release-keys.7z` (fuera del repo).

## Archivos clave
- `services/localReminders.ts` + `services/pushNotifications.ts`: las dos mitades del sistema hibrido de notificaciones.
- `android/.../PersistentNotificationService.kt`: Foreground Service que muestra la notificacion fija, se refresca solo cada 60s, sobrevive con la app cerrada.
- `scripts/supabase-admin.mjs`: cliente de Supabase con la service role key, usado solo por los scripts (nunca en el cliente).
- `src/lib/deviceId.ts` + `services/deviceSubscription.ts`: reemplazo del "codigo de 6 digitos" — cada instalacion genera un UUID local propio para registrar su token FCM + favoritos en `device_subscriptions`, sin login.

## Instalar y correr
Dentro de `project/`:
```
npm install
npx react-native run-android
```
Dentro de `project/scripts/` (para los scrapers, requiere Node 22):
```
npm install
node sync-matches.mjs
```
